# IHC-A-11 · Prueba de usabilidad a 360 px

## Datos

- Fecha/hora: 28/10/2026.
- Participante: Daniel Luis.
- Ancho del viewport: 360 px.
- Prototipo: v1 / v2, según la versión evaluada.

## Tarea

Completar el campo visible del Dashboard sin perder el orden lógico del foco.

## Preguntas y respuestas

### 1. ¿Qué elemento buscas primero al abrir la pantalla?

Buscaría el título del Dashboard y el indicador del paso actual. Después identificaría el campo que debo completar para entender cuál es la acción principal.

### 2. ¿Puedes identificar el paso actual?

Podría identificarlo si el indicador de progreso utiliza una etiqueta clara o un estilo visual diferente para destacar la etapa actual. Si solamente cambia de color y no tiene texto, podría resultar menos evidente.

### 3. ¿Se superpone u oculta algún campo?

Esperaría que el campo y su etiqueta fueran completamente visibles en la pantalla. Revisaría también que el teclado virtual no cubra el control mientras escribo y que los botones sigan siendo accesibles.

### 4. ¿El orden Stepper → título → card → acción resulta natural?

Sí, porque primero puedo identificar mi posición en el proceso, después comprender la tarea, revisar la información relacionada y finalmente ejecutar la acción. Considero que ese orden facilita la navegación.

### 5. ¿La etiqueta y su control parecen pertenecer al mismo grupo?

Deberían estar próximos y alineados para que resulte evidente qué información debo ingresar en cada campo. Si la etiqueta está demasiado separada del control, podría confundirme al relacionarlos.

### 6. ¿Qué contenido quitarías o agruparías para reducir carga mental?

Reduciría las instrucciones repetitivas y agruparía los datos relacionados dentro de una misma tarjeta. Mantendría el indicador de progreso, el título, el campo que debo completar y la acción principal, procurando que todo se visualice correctamente en los 360 px de ancho.
